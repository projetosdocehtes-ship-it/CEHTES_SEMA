PUBLICACAO CEHTES SEMA

1. CONFIGURACAO
Abra o arquivo .env nesta pasta no Bloco de Notas.
CEHTES_REPOSITORIO: URL HTTPS do repositorio, sem virgula no final.
CEHTES_BRANCH: main para as proximas atualizacoes.
Publicar-CEHTES.bat fixa -Branch main, mesmo se o .env indicar outra branch.
O uso direto do PowerShell sem -Branch continua lendo CEHTES_BRANCH.
CEHTES_ORIGEM: pasta cujas subpastas serao copiadas.
CEHTES_COPIA_REVISADA: caminho de uma copia temporaria previamente revisada.
GITHUB_USUARIO: preencha com seu login pessoal autorizado no GitHub.
Nao coloque senha ou token. O .env fica excluido da publicacao.
Use caminhos literais; variaveis como %USERPROFILE% nao sao expandidas.

2. ACESSO AO REPOSITORIO
A conta bierley123 recebeu erro 403 no envio anterior.
O dono pode conceder acesso pelo repositorio > Settings > Collaborators
(ou Collaborators & teams), e o convidado precisa aceitar o convite.
Se voce usa outra conta com acesso de escrita, use esse login no .env.
O nome do dono do repositorio pode ser uma organizacao: nesse caso,
autentique sua conta pessoal com acesso, nao o nome da organizacao.

3. AUTENTICACAO
No PowerShell, substitua SEU_LOGIN pelo mesmo login colocado no .env:

git credential-manager github login --username SEU_LOGIN --browser --force

No navegador, confira qual conta esta conectada e conclua o login e 2FA.
O Git Credential Manager guarda a credencial fora dos scripts.
Este comando foi conferido no Git Credential Manager instalado.
Alterar git user.name ou user.email nao muda a conta autenticada.

4. ENVIO
Reenviar-CEHTES-Revisado.bat envia o commit ja preparado, sem refazer copia.
Ele confere se o repositorio e a branch da copia coincidem com o .env.
Publicar-CEHTES.bat prepara uma nova copia com os arquivos atuais,
incluindo os scripts novos, mostra a revisao e pede PUBLICAR antes do envio.
Se a branch ja existe no remoto, a nova copia parte dela e faz push normal,
sem force. O BAT publica diretamente na main, sem etapa de integracao.
Para outra branch, use Publicar-CEHTES.ps1 -Branch NOME explicitamente.
As subpastas sao copiadas com /E, sem /MIR. Arquivos remotos ausentes na
origem local sao preservados, incluindo o README.md da pagina inicial.
README.md e AgenteIA/README.md devem existir e nao podem estar vazios.
Se houver uma versao local, ela atualiza a correspondente no GitHub.
Para editar o README inicial localmente, use README.md na CEHTES_ORIGEM;
o README da pasta AgenteIA fica em AgenteIA/README.md nessa mesma origem.
Para usar Reenviar, mantenha a branch correspondente a copia revisada.
Nao apague a copia temporaria antes de concluir o envio do commit revisado.

5. VALIDACAO SEM ENVIO
Na pasta destes arquivos:
powershell.exe -NoProfile -File .\Publicar-CEHTES.ps1 -VerificarConfiguracao
powershell.exe -NoProfile -File .\Reenviar-CEHTES-Revisado.ps1 -VerificarConfiguracao

Se continuar o erro 403, confira o login no .env, a conta autenticada,
o aceite do convite e a permissao de escrita. Repositorios de organizacao
podem exigir autorizacao adicional definida pela organizacao.
